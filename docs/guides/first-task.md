title: Create your first task
description: Finish a draft first, then set up a continuous content task as you need it.
---

The workbench handles content in a single conversation, and continuous content tasks run on a schedule. Getting one reviewable draft from real material first, then configuring the schedule and platform delivery, makes results much easier to check.

## Finish a conversation task first

1. Open "continuous conversation" in the workbench.
2. Select an installed skill; when you need tools, open "Apps and plugins" to pick this round's scope.
3. Write out the material, audience, goal, delivery form, and which information is still uncertain.
4. Check the output after sending; use the office documents plugin when you need a file.

## Set up a continuous content task

In "Multi-platform tasks" or the task list, open the content task form and fill in the entrances your current accounts allow:

| Setting | How to fill it |
| --- | --- |
| Task name | A name you will recognize, like "weekly product knowledge draft" |
| Target platform and account | Choose accounts you are allowed to use; check platform and account capabilities first |
| Topic and goal | State the content scope, the readers and the form you want |
| Content template | Choose as needed; check the default targets a template brings in |
| Skills | Only installed methods you may use; a content automation task takes at most 10 |
| Assets and images | Use existing assets, or configure image generation when the service supports it; videos use available video assets |
| Generation schedule and timezone | Pick an interval or a fixed daily time, and verify the timezone |
| Total target | Follow the delivery basis the form shows: publish, content or draft delivery |
| Review mode | For first use, keep "manual review before publish" |

A workbench round selects at most **3 skills**; the content automation task form takes at most **10**. These are two different entrances.

## Check before saving

Read the form's missing-field notices and account capability notices first. If the page says "local drafts only", "draft delivery" or "capability pending", use the task within that scope; do not treat a created task as submitted or published work.
